- 2026-10-24 10:30 — **기본 zzap 프리셋은 지울 수 없게 + 저사양 프리셋 삭제.** ① 기본 프리셋(zzap 쉬움·보통·zzap·TEST)은 읽기 전용입니다. 고쳐서 저장하면 '[Modified]' 복사본으로 저장되고 게임은 복사본을 씁니다. 복사본은 고치고 지울 수 있지만 원본은 F6(옛 프리셋 관리의 '삭제'도 포함)·웹·서버 어디서도 지워지지 않습니다. 전에는 F6 옛 프리셋 관리 화면과 서버 삭제 요청으로 원본 파일이 지워질 수 있었습니다. ② 'zzap 저사양 [테스트]' 프리셋을 뺐습니다. 같은 효과는 어느 프리셋에서든 '빠른 설정 › 저사양 PC' 스위치로 켭니다. 이미 설치된 옛 파일은 서버가 시작할 때 지우고, 직접 만든 복사본('zzap 저사양 [테스트] [Modified]' 등)은 남깁니다. 그 프리셋을 쓰고 있었다면 다음 실행 때 zzap이 선택됩니다. 확인: 서버 빌드 오류 0, 클라 새 오류 0, 회귀 검사 35/0·웹 정적 검사 35/0(프리셋 카드가 하나 줄어 1개 감소). 게임·웹 실제 클릭은 미검증.
- 2026-10-24 09:56 — **어제 설정 화면 작업 검토 + 오류 수정.** ① F6에서 zzap 기본 프리셋을 고치고 저장하면 '[Modified]' 복사본은 서버에 저장되는데, 저장 순서가 바뀌면서 바로 뒤의 '이름이 이미 있음' 검사에 걸려 이름이 '… Copy(0)'으로 바뀌었고, 그런 프리셋은 없어서 게임이 원본 zzap을 다시 불러왔습니다(저장한 값이 적용 안 된 것처럼 보임). 이제 빈 이름을 먼저 정하고 목록에 올린 뒤 저장합니다. ② 저장이 거절되면(편집 금지·기본 프리셋 이름·서버 오류) 목록에 가짜 항목이 남거나, 내부 기본 프리셋이 '현재 프리셋'으로 바뀌어 남던 문제를 막았습니다. 고친 값은 '저장 안 됨'으로 그대로 남습니다. F6 빠른 설정 탭의 '복사본 만들기'도 같습니다. ③ F6 프리셋 관리의 '정보 저장'(이름 바꾸기)이 새 이름 저장 전에 옛 파일부터 지워서, 저장이 막히면 프리셋이 사라질 수 있었고 zzap 원본 파일도 지울 수 있었습니다. 이제 새 이름 저장이 성공한 뒤에만 옛 파일을 지우고, zzap 원본은 지우지 않습니다(원본은 그대로, 새 이름은 복사본). ④ 서버가 저장을 거절한 답('Ok: false')을 게임이 무시하고 저장된 것으로 처리하던 것을 고쳤습니다. 서버도 기본 프리셋 이름으로 온 저장 요청에 오류를 내지 않고 '저장 안 됨'으로 답합니다. 옛 폴더형 프리셋 가져오기에 기본 프리셋 이름이 섞여 있으면 시작 시 가져오기가 통째로 멈추던 것도 건너뛰게 했습니다. ⑤ 웹 봇 종류 페이지의 '고급' 칸 제목 `@section.Label`이 Razor 예약어(`@section`)로 읽혀 서버 빌드가 실패하던 것을 `@(section.Label)`로 고쳤습니다. ⑥ 웹 '새 프리셋'에서 기본 프리셋 이름이 복사본 이름으로 바뀌어 저장돼도 실제 저장된 이름을 엽니다. 장비 은밀성 화면은 비교 프리셋에 장비 목록이 없어도 오류 없이 저장값으로 비교합니다. 확인: 서버 빌드 오류 0(기존 경고 16), 클라 새 오류 0(Unity 2022 전용 레이캐스트 기준선 14개), 회귀 검사 34/0·웹 정적 검사 36/0 통과. 게임·웹 실제 클릭은 미검증 — 이상하면 이 커밋만 되돌리면 됩니다.
