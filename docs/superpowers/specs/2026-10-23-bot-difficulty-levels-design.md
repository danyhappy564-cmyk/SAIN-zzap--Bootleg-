# 봇 종류별 v2: 봇마다 난이도 고르기 + 성격 설명 번역 — 설계

- 이전 설계: `2026-10-23-bot-type-settings-redesign-design.md` (v1). 이 문서가 바꾸는 곳만 적는다 — 나머지(손잡이 9개 정의, 고급 목록, 복사, 스폰 기록)는 v1 그대로.

## 1. 왜

사용자(2026-10-23, v1 첫 확인): 쉬움/보통/어려움/불가능 버튼을 "킬라 → 어려움을 고르면 킬라가 어려움에 맞게 바뀐다"로 이해했는데, v1은 '어느 난이도 꼬리표의 설정을 고칠지' 고르는 버튼이었다. zzap 프리셋은 대부분 봇이 4칸 같은 값이라 눌러도 변화가 없어 "바뀐 건지 모르겠다". 이름 옆 '기록 없음' 대신 고른 난이도가 보이길 원함.

## 2. 결정 (사용자)

- 난이도를 고르면 **SAIN 값이 단계 값으로 바로 써 넣어진다**(방식 A). 게임 실행 코드는 안 바뀐다.
- 단계 기준은 **zzap 프리셋 순서**: 쉬움 = 'zzap 쉬움' 수준, 보통 = 'zzap 보통' 수준, 어려움 = 'zzap' 그대로, 불가능 = zzap보다 더 세게.
- 단계를 바꾸면 손으로 조정한 값은 그 단계 값으로 덮어써진다(미리 경고).

## 3. 화면 (F6·웹)

- **왼쪽 목록 배지**: 고른 난이도(쉬움 파랑·보통 회색·어려움 주황·불가능 빨강). 고른 뒤 값이 달라졌으면 `어려움 (조정됨)`. 고른 적 없으면 값이 '어려움(zzap)' 계산값과 같을 때 `어려움`, 아니면 `직접 설정`(보라). v1의 스폰 기록 배지는 없앤다.
- **오른쪽 맨 위**: 단계 버튼 4개 `쉬움(약하게) · 보통 · 어려움(zzap 그대로) · 불가능(아주 세게)`, 지금 단계 강조. 손 조정이 있으면 `⚠ 손으로 조정한 값이 N개 있습니다 — 다른 난이도를 누르면 그 단계 값으로 바뀝니다`.
- **손잡이 9개**: v1 그대로, 항상 4칸 전부에 적용(기본 화면의 칸 고르기 버튼·'지금 보는 칸' 줄 없앰). 막대 기준 눈금·차이·되돌리기의 기준 = **고른 단계의 계산값**(고른 적 없으면 '어려움' 계산값). 성격 지정·수류탄은 `난이도와 무관`.
- **고급**: 숫자 전부 + `난이도별로 따로 바꾸기`(v1의 칸 고르기: 4칸 전부/쉬움/보통/어려움/불가능) + `실제로 나온 난이도: 보통 3명 (최근 5판)`(v1 스폰 기록). '4칸 같음' 안내와 '칸마다 다름'·칸별 값 표시도 여기로.

## 4. 단계 값 계산 (공용, 순수 함수)

입력: 봇 그룹, 고른 단계, **기준 봇 값**(zzap 번들의 같은 봇, 없으면 서버 SAIN 기본 번들(`PresetSync.TryGetServerDefault`/웹 `PresetGeneration`)의 같은 봇, 그것도 없으면 지금 값), **단계 프리셋 3개의 전역 값**(번들 'zzap 쉬움'·'zzap 보통'·'zzap'에서 읽음, 하드코딩 아님), **지금 로드된 프리셋의 전역 값**.

기준 = 기준 봇의 `normal` 칸. 결과는 4칸 모두에 같은 값(봇이 어떤 꼬리표로 나와도 그 단계).

단계 L의 전역 값을 G_L, 지금 프리셋 전역 값을 G_cur라 할 때, 봇별 값 = 기준 × (G_L / G_cur):

| 봇별 값 | 전역 짝 | 비고 |
|---|---|---|
| `Core.VisibleDistance` | `Difficulty.VisibleDistCoef` | |
| `Core.GainSightCoef` | `Difficulty.GainSightCoef` | |
| `Shoot.AUTOMATIC_FIRE_SCATTERING_COEF`, `Aiming.COEF_IF_MOVE` | `Difficulty.ScatteringCoef` | |
| `Core.HearingDistanceMulti` | `Difficulty.HearingDistanceCoef` | |
| `Core.AccuratySpeed` | `Difficulty.ACCURACY_SPEED_COEF` | |
| `Shoot.RecoilMultiplier` | `Shoot.BOT_RECOIL_COEF` | 봇별 범위 0.25~3에서 잘림 — zzap 쉬움의 30배 차이는 3배에서 멈춤(알려진 한계) |
| `Aiming.FasterCQBReactions` | `Aiming.FasterCQBReactionsGlobal` | 값 그대로(bool) |
| `Aiming.MAX_AIM_TIME` (+ 조준 속도 손잡이의 나머지 3개는 같은 비율) | — | 단계 번들의 같은 봇 값. 그 봇이 번들에 없으면 기준 × (단계 번들 pmcUSEC / zzap pmcUSEC) |

- `PRECISION_SPEED_COEF`는 봇별 짝이 없어 쓰지 않는다(알려진 한계).
- 지금 프리셋이 무엇이든 같은 뜻: 'zzap 쉬움' 프리셋을 쓰는 중에 킬라만 '어려움'이면 킬라는 zzap 수준(G_cur로 나눠 상쇄).
- **어려움** = 위 식에서 G_L = zzap 전역(지금 프리셋이 zzap이면 기준 그대로).
- **불가능** = 어려움 결과에 v1 표의 불가능 배율: 조준 시간 ×0.6, 탄 퍼짐 ×0.7, 발견 ×1.5, 시야 ×1.2, 청각 ×1.2, 머리 노리기 확률 ×1.5, 공격성 ×1.2.
- 머리 노리기·공격성은 zzap 세 프리셋이 같아 쉬움·보통·어려움에서 기준 그대로.
- 모든 값은 필드 `[MinMax]`로 자른다. 단계 번들 중 하나라도 없으면 그 단계 버튼은 꺼짐(이유 툴팁).

## 5. 저장

- `SAINSettingsGroupClass`에 `[DataMember] public EBotLevel DifficultyLevel = EBotLevel.None;` (`None, Easy, Normal, Hard, Impossible`). 옛 프리셋엔 없음 → None.
- `(조정됨)` 판정 = 저장된 단계의 계산값과 지금 값(단계가 쓰는 필드 + 손잡이 필드)을 비교(1e-4).
- 프리셋 형식에 필드 1개 추가 — 서버 역직렬화는 없으면 기본값(기존 `PersonalityOverride` 채우기와 달리 채울 필요 없음, None이 맞음).

## 6. 번역 버그 (순서 1)

- 원인: 성격 설명이 프리셋 JSON에 글자로 저장됨. bundled zzap 프리셋의 기가차드 설명은 한글(영어 모드에서도 한글), 렉리스는 옛 영어 문장("This personality can only be assigned to Twitch Players…")이라 번역표에 없음(한글 모드에서도 영어).
- 고침: F6·웹의 성격 설명은 프리셋 글자 대신 코드의 `PersonalitySettingsClass.PersonalityDescriptions[personality]`를 쓰고, 그 8문장의 한국어를 `KoreanSettingText`에 넣는다.
- 검사(selftest): 네 탭(전역·봇·성격·장비 은밀성) 설정의 영어 이름·설명 원문에 한글이 섞여 있지 않다; 성격 탭 필드는 한국어 이름·설명이 모두 있다. 전역·장비 은밀성의 누락 개수는 세어서 5·4번 작업에 넘긴다(이번엔 안 고침).

## 7. 확인

- selftest: 단계 계산(쉬움/보통/어려움/불가능, 지금 프리셋 상쇄, 기준 없는 봇, 단계 번들 없음, 범위 자르기, 4칸 같음), `(조정됨)` 판정, 배지 문구, 번역 검사.
- 빌드 오류 0, 경고 클라 3·서버 16.
- 게임: 킬라 → 어려움 → 숫자 바뀜·배지 `어려움`, 조준 속도 만지면 `어려움 (조정됨)`, 다른 프리셋 쓰는 중에도 같은 숫자, 영어 모드 성격 설명 영어/한글 모드 렉리스 한글. 웹은 서버 켜면 Claude가 확인.

## 8. 안 하는 것

- 3~5번 탭(각자 설계).
- 스폰 꼬리표 강제(사용자가 A 선택).
- 단계 배율 표 외의 스타일 값 변경.

## 9. 추가 결정 (사용자, 목업 bot-v3c 승인)

### 9.1 단계가 따라가는 범위 (zzap 세 프리셋 전체 비교 결과)

- **봇별 값 7개는 단계 번들의 같은 봇 값을 그대로 복사**: `Shoot.FireratMulti`, `Shoot.BurstMulti`, `Core.VisibleAngle`, `Aiming.MAX_AIM_TIME`(조준 속도 손잡이 나머지 3개는 같은 비율), `Move.STRAFE_SPEED`, `Aiming.MAX_AIMING_UPGRADE_BY_TIME`, 그룹 `DifficultyModifier`. 그 봇이 단계 번들에 없으면 기준 × (단계 번들 pmcUSEC 값 / zzap pmcUSEC 값).
- **능력치 전역 값**은 4절 표대로 비율로(시야·발견·퍼짐·청각·조준 정확 속도·반동·근접 빠른 반응).
- **행동 전역 값 27개(문 전술·근접전·위치 바꾸기·분대)는 따라가지 않는다** — 사용자: "성격 지정이 있으니 필요 없음". 단계 버튼 아래 안내: `행동(문 전술 등)은 성격과 전역 설정을 따릅니다`.
- 반동(`RecoilMultiplier` 0.25~3)·조준 정밀 속도(봇별 값 없음)는 4절 한계 그대로 — 사용자 결정 대기 항목(범위 30으로 넓히기 제안).

### 9.2 단계 버튼 글자

`쉬움 — zzap 쉬움 프리셋 수준`, `보통 — zzap 보통 프리셋 수준`, `어려움 — zzap 프리셋 수준`, `불가능 — zzap보다 더 세게`. 지금 단계는 `· 지금`.

### 9.3 봇별 AI 선택 (SAIN / 게임 기본)

- 단계 버튼 위 `이 봇의 AI: [SAIN] [게임 기본 (바닐라)]`. 바닐라면 아래 단계·손잡이 흐림. `게임 재시작 후 적용`.
- 저장: `SAINSettingsGroupClass.UseVanillaAI` (`[DataMember] bool`, 기본 false).
- 적용: 게임 시작 때 `BigBrainHandler`의 기존 바닐라 토글(`ToggleVanillaLayersFor…`)과 같은 방식으로, `UseVanillaAI`인 봇 종류만 SAIN 레이어를 빼고 바닐라 레이어를 둔다. 전역 '바닐라 OO 전체'가 켜져 있으면 그쪽이 우선이고 화면에 그 이유(`전역 설정 '바닐라 보스'가 켜져 있음`)를 보이고 버튼을 끈다.
- 목록 배지 `바닐라`(회색). 게임 실행 코드 변경이라 1차 시뮬 미링크 여부 확인 + 게임 확인.

### 9.4 팩션 한꺼번에 · 접기

- 왼쪽 팩션 줄(`BotType.Section`): ▾/▸ 화살표 = 접기(상태 기억), 이름 = 팩션 선택.
- 팩션 선택 화면: `PMC 전체 (2종)`, AI(전부 같으면 그 값, 섞이면 '섞임'), 단계 버튼(아래 줄에 지금 그 단계인 봇 수), 되돌리기·원본 사용, 봇별 표(이름·단계 배지·AI). 누르면 팩션 안 봇 전부에 적용. 손잡이는 봇 하나에서만.

### 9.5 되돌리기 · 원본 사용 (봇·팩션 공통)

- `되돌리기` = 마지막으로 저장한 값으로(저장 안 한 변경 취소) — 그 봇의 4칸·단계·AI.
- `원본 사용` = 기준(zzap, 없으면 SAIN 기본)의 값으로 4칸 복사, 단계 None, AI SAIN.
